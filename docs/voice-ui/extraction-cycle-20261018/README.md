部品供給済みの表現R2/2、不足補完0/2という[前回結果](../quota-cycle-20261018/README.md)は保持する。表示名保持指示、在庫差分、低confidence保留は既存であり、新しい打開策と数えない。原文名が汎用名へ置換された箇所は分かるが、質問・型・文脈・モデルの内部原因は未証明である。

## 評価と証拠

[公開正解と評価条件](diagnostic.oracle.json)はcallerへ入力しない。全16枠を分母に保持し、原request/response、観測済HTTPエラー・契約拒否、構造INVALID、応答なしの通信不明、意味誤り、完全一致を分ける。有効応答には閉response・request_id・slotsとrequiredの一致も要求する。同じcase/repで双方が有効な組だけ意味精度を比較し、契約成立率の差は別記する。

同じ完成Workerをキー不要で動かして捕捉するType送信bodyと、公開HTTP原bytes・完成物/source同一性で因子差を束縛する。これはfixture応答による送信形式検証であり、live upstream bodyを直接保存した証拠でも、モデル品質でもない。typellm-latestの解決先モデル版は未観測とする。実測原応答とprovider送信ログは別に保持する。鍵本体・headers・環境全体は記録しない。

結果が繰り返し一貫すれば、その有限条件を次の仮説候補とする。混在なら判別未成立、全条件同じなら今回の比較では切り分けられなかったとする。製品EFFECTやNO_EFFECT、未見品質、Type一般の有効・無効へ昇格しない。

rootがcallerと実行、同じ独立担当1名が契約・完成物・送信0・原応答・精算を独立確認する。公開登録とwire差の確認 → 同じ実プロセスの送信0を双方が確認 → 16枠実行 → 物理停止・精算 → 独立評価、で一度閉じる。開始前の不一致やcap超過懸念は実送せず停止する。実行中の各HTTP失敗はその枠を保持し、残る予定枠だけを実行する。最終停止不成立・送信数不明は次段へ進まない。
