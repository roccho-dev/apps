## One intervention

The sole proposed product change is `quotaGoalBundle(bundle, required)` and its call in completion.mjs. It validates closed full-NEW label/kind/quantity rows and unique finite part keys, then stably filters the existing local parts in original order to at most the requested quantity of each exact label/kind. It returns a frozen local bundle; invalid input returns null. Insufficient stock returns the available minimum, not invented parts. It does not derive requirements, create candidates, change labels/kinds/purposes/keys, or generate parents, edges or operations.

Normal runInventoryGoal invokes it after existing deterministic materialization and before runGoal whenever an accepted v2/v3 full-required receipt exists. Both literal-v2 and adaptive-v3 therefore use quota. Legacy paths without a full-required receipt retain their existing behavior. No extra product mode, user setting, API schema or provider call is introduced. R's explicit open arm calls the same source runGoal with its unfiltered supplied stock; R's quota arm uses the same product helper before that runGoal.

G0/F/V questions, contexts, .5 thresholds, HTTP contracts and upstream request bytes remain unchanged. Ops, UI, envs and launcher heads stay fixed. Goal/core6 and renderer bytes remain unchanged. Actual completed-Worker keyless ablations must prove the old/new G0/F/V upstream-byte equality before live admission. The product helper must be tested for empty requirements, min-capacity, stable order, same-label different-kind, repeated quantities, invalid fields/duplicates and one-use keys. No test may synthesize a terminal NONE or send an extra request to make a trace look like the old trace. Exhausted quota may legitimately end existing Goal as `no-executable-delta`.

## Fresh classification

Fresh R has two pairs. Pair admission requires same complete supply/full-NEW requirements/initial state, exact source and legal protocol, preserved pre-existing semantics, valid execution, deadline, actual finite paint and persistence on both arms. It does not require open graph-exact/no-false-adoption: excess additions are retained as open failures. Quota quality needs 2/2 exact full graphs, required counts and no excess. Assembly effect additionally needs at least one admitted open-failure/quota-exact gain and zero quota regressions. This is a finite assembly effect only. NO_EFFECT is allowed only for both complete valid admitted pairs, quota2/2, open2/2 and zero gains; it means no observed gain in these two registered conditional examples. Invalid, missing or inadmissible evidence is UNPROVEN; failed quota quality is UNMET, not NO_EFFECT.

Quality denominator remains all six; C needs6/6 exact, S2/2 generation-free/Type0, controls2/2 unchanged/Type0, no false adoption, deadline/paint/persistence. Both missing cases are independently verified literal deficits before sealing. Actual causal pair admission needs matching initial literal observations and both arms' actual existing policy eligibility. A gain requires B unchanged/failing and C correct required/proposal/V/materialization/whole graph with paint and persistence. Effect needs both registered M2 admitted and gains2, regression0, no false adoption, all guards and full browser evidence. One gain is a partial observation with effect UNMET; it is not rounded into success.

E NO_EFFECT is limited to all two registered missing opportunities actually admitted with complete valid evidence, zero gains, no regressions/false adoption, all S/control guards, actual paint/persistence and all retained denominators. A valid rejected proposal or conservative stop is an observed non-gain; malformed/unknown calls or a missing/ineligible opportunity cannot establish NO_EFFECT. E whole quality remains separately reported even when this finite no-gain condition is met. No general ineffectiveness, R assembly gain, or improvement in the old frontier taxonomy is inferred.
